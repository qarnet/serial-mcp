### Fuzz job

Use matrix with all three targets and `fail-fast: false`. Per matrix job:

1. checkout;
2. install normal Ubuntu serial build dependencies (`libudev-dev`,
   `pkg-config`);
3. install pinned `nightly-2026-07-15` with
   `dtolnay/rust-toolchain@nightly-2026-07-15` (no floating nightly);
4. print `rustc --version --verbose`;
5. cache Cargo/fuzz target appropriately;
6. install pinned tool using
   `cargo install cargo-fuzz --locked --version 0.13.2`;
7. run selected target with libFuzzer `-max_total_time=300` and an outer GNU
   `timeout` no greater than 360 seconds;
8. job `timeout-minutes` no greater than 12;
9. on failure, upload target-specific `fuzz/artifacts/<target>/` and
   `fuzz/corpus/<target>/` with short retention. Missing paths may warn but must
   not mask original failure.

Use `actions/upload-artifact@v4`; artifact names include matrix target.

### Mutation job

Use Rust `dtolnay/rust-toolchain@1.88.0`, print version, cache Cargo, install
`cargo-mutants 27.1.0` with `cargo install --locked --version`, then run focused
mutations only for:

- `src/checksums.rs`;
- `src/framing/parsers/**` (quote glob).

Use repeated supported `--file` filters, `--cargo-arg=--locked`, `--timeout 120`
per mutant, bounded parallel jobs (2 is sufficient), and only library tests
(`-- --lib`). Keep baseline enabled. Wrap whole command in GNU `timeout` no
greater than 1500 seconds and set job `timeout-minutes` no greater than 30.
Missed/time-out mutants must fail job; do not suppress exit status.

On failure upload `mutants.out/` with `actions/upload-artifact@v4`, short
retention, and no masking of original failure.

## Windows serial-e2e investigation

Create `docs/development/windows-serial-e2e-investigation.md` and index it from
`docs/development/README.md`. Record:

- Windows real serial E2E needs real/virtual COM device, not a named pipe;
- com0com is a kernel-mode virtual serial driver; common upstream builds are
  test-signed/driver-signature-sensitive and may require administrator setup,
  test-signing/security changes, or reboot;
- GitHub-hosted ephemeral runner driver install is not an acceptable default
  trust/reliability trade-off for this project;
- self-hosted pre-provisioned signed-driver runner or physical loopback hardware
  could support it later, but no such runner exists now;
- current Windows CI still compiles/runs unit tests, while injectable
  `SerialIo`/controlled HTTP tests cover lifecycle behavior without OS COM;
- decision: no privileged driver installation; keep Windows serial E2E deferred
  until a pre-provisioned runner/approved design exists.

Identify evidence sources by URL (com0com project/readme and GitHub runner docs),
but do not claim weak third-party/community distributions are official signed
Microsoft-supported packages.

Remove completed hardening and Windows-investigation sections from FEATURES.
Update AGENTS with exact hardening schedule/manual status, pinned tools, bounds,
artifact behavior, and Windows decision. No README user-facing change needed.
